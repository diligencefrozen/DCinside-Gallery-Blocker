# DCB 공격적 표현 감지 Student 모델 카드

## 용도와 한계

이 모델은 디시인사이드에서 사용자가 현재 보고 있는 한국어 댓글과 게시글 본문 중 불쾌감을 줄 수 있는 공격적 표현을 기기 안에서 우선 가리는 보조 기능입니다. 개인의 성향·의도·정체성을 판정하거나 제재를 결정하는 용도로 만든 모델이 아닙니다. 결과는 틀릴 수 있으며 사용자는 `이번만 보기`로 원문을 확인할 수 있습니다.

인용·비판 맥락을 충분히 이해하지 못합니다. 예를 들어 공격 표현을 인용해 사용하지 말라고 한 문장도 가릴 수 있습니다. 학습 자료의 문체·시기·주제 편향을 이어받을 수 있고, 새로운 은어와 우회 표현을 놓칠 수 있습니다. 합성 점검에서 `존맛`은 오탐했고 `개이득`은 가리지 않았습니다. 이러한 소수 문장은 공식 정확도 산출용 자료가 아니라 알려진 실패 형태를 확인하기 위한 점검입니다.

## 자료와 분리

사용자가 제공한 세 원본 archive를 독립 파이프라인으로 읽었습니다. Curse Detection Data 5,825행, Korean HateSpeech/BEEP! 8,367행, Korean Malicious Comments 10,000행(바깥 따옴표 때문에 깨진 25행 복구)으로 총 24,192행입니다. Malicious Comments의 원래 `0`은 공격적, `1`은 정상으로 변환했습니다. BEEP!의 none/offensive/hate, bias, gender 보조 주석은 teacher 보조 head에 유지했습니다.

NFKC 정규화 뒤 구두점·공백 차이를 제거한 group 단위로 먼저 중복을 묶었습니다. 상충 label 1개 group은 제외했고, 일관된 17,437개 group을 train 12,205 / validation 2,616 / evaluation 2,616으로 분리했습니다. 따라서 같은 내용의 변형이 split 양쪽에 걸치지 않습니다.

BEEP! unlabeled 댓글 2,033,893개를 모두 순회했습니다. 사람 label 자료와 겹친 9,572행은 제외하고 2,024,321행을 teacher로 채점했으며, 중복 group을 다시 합친 58,428개를 distillation에 사용했습니다. 원문, teacher, pseudo corpus와 checkpoint는 배포 파일에 포함하지 않습니다.

## 구조와 선택

Teacher는 문자 1–5-gram TF-IDF logistic multi-task 모델입니다. Student는 실제 학습된 16차원 문자 n-gram 임베딩 합산과 32-unit residual MLP이며, 사람 label BCE·temperature-2 teacher soft logit·보조 head logit loss를 함께 사용했습니다. 후보 선택과 임계값은 validation에서만 했습니다.

FP32 모델은 7,684,150바이트, INT8 모델은 2,404,471바이트입니다. 균형 임계값에서 두 후보의 validation F1은 모두 `0.7309`였고 최대 출력 확률 차이는 `0.00228`이어서 INT8을 선택했습니다.

균형 설정의 source별 F1은 Curse `0.7568`, BEEP! `0.6447`, Malicious Comments `0.7942`였습니다. 길이별 F1은 20자 미만 `0.6716`, 100자 초과 `0.8333`입니다. BEEP! 댓글에 제목을 더하면 recall은 `0.5167 → 0.5947`로 올랐지만 FPR도 `0.1144 → 0.1882`로 늘어 댓글 실행 경로에서는 제목을 쓰지 않습니다. 게시글 본문은 별도 실험 기능입니다.

Python ONNX Runtime 단일-thread 측정에서 INT8 1건 추론 중앙값은 약 `0.017ms`, p95는 `0.038ms`였습니다. 이는 토크나이징·브라우저 worker 최초 로딩을 제외한 참고값이며 기기별 성능을 보장하지 않습니다.

Chrome for Testing의 실제 extension worker를 네트워크 오프라인 상태로 실행한 측정에서는 최초 모델 준비와 1건 추론이 약 `234ms`, 이후 1건 중앙값/p95가 `0.1/0.3ms`, 4건 batch가 `0.3/0.5ms`였습니다. 측정 페이지의 JS heap 표시는 약 1.53MB에서 1.64MB로 변했지만 WASM 메모리 전체를 나타내는 값은 아닙니다. 전용 worker를 종료한 뒤 브라우저가 보고한 worker 수는 1개에서 0개가 됐습니다. 값은 해당 기기와 실행에서 얻은 참고치이며 성능이나 메모리 사용량을 보장하지 않습니다.
