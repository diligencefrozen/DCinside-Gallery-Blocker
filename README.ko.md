# 디시갤 차단기

**Less noise. More focus.**

보고 싶지 않은 갤러리와 글, 댓글, 사용자, 이미지 등을 가려

## 왜 만들었나요?

디시인사이드를 이용하다 보면 보고 싶지 않은 글이나 댓글을 여러 곳에서 다시 마주치게 됩니다.

특정 갤러리에 들어가지 않더라도 검색 결과나 최근 방문 목록, 다른 글의 링크, 인기 글 목록 등에서 다시 보일 수 있습니다.

처음에는 제가 보고 싶지 않은 갤러리를 가리기 위해 작은 차단 기능을 만들었습니다.

하지만 쓰다 보니 갤러리 하나를 막는 것만으로는 부족했습니다.

글과 댓글, 특정 사용자, 낚시성 제목, 이미지처럼 신경 쓰이는 요소를 따로 가릴 필요가 생겼고, 기능을 하나씩 더하면서 지금의 확장 프로그램으로 발전했습니다.

이 프로그램이 하려는 일은 단순합니다.

> **무엇을 볼지는 사용자가 직접 정할 수 있어야 합니다.**

## 무엇을 할 수 있나요?

### 갤러리 차단

갤러리 주소나 갤러리 아이디를 등록해 들어가지 않도록 설정할 수 있습니다.

차단 방식도 선택할 수 있습니다.

* **스마트 차단** — 먼저 경고 화면을 보여 줍니다. 그래도 들어가고 싶다면 한 번은 들어갈 수 있습니다.
* **돌아가기** — 경고 화면을 보여 준 뒤 일정 시간이 지나면 이전 페이지로 돌아갑니다.
* **강력 차단** — 해당 갤러리가 열리기 전에 브라우저에서 바로 막습니다.

차단한 갤러리로 이어지는 링크도 다른 화면에서 숨길 수 있습니다.

### 글과 댓글 정리

다음과 같은 기준으로 보고 싶지 않은 내용을 숨길 수 있습니다.

* 특정 단어가 들어간 글
* 특정 사용자
* 특정 아이피
* 특정 닉네임
* 익명 사용자의 글
* 이미지
* 디시콘
* 댓글
* 공지
* 설문
* 일부 자동 작성 콘텐츠

### 실시간 베스트도 정리할 수 있습니다

**실시간 베스트**는 디시인사이드에서 인기 있는 글이나 화제가 되는 글을 모아 보여 주는 곳입니다. 사람들이 인기 글을 읽고 댓글을 달며 이야기를 나누는 공간이기도 합니다.

차단한 갤러리의 글이나 보고 싶지 않은 내용이 실시간 베스트에 나타나는 것도 따로 조절할 수 있습니다.

### 그 밖의 편의 기능

* 사용자마다 개인 메모 남기기
* 목록에서 글 내용 미리 보기
* 글 목록 자동 새로 고침
* 목록을 더 촘촘하게 보기
* 글꼴과 글자 크기 바꾸기
* 필요 없는 화면 영역 숨기기
* 화면 모양 바꾸기
* 설정과 차단 목록을 파일로 백업하고 복원하기

## 어떻게 발전했나요?

처음부터 지금처럼 기능이 많은 프로그램을 계획한 것은 아닙니다.

제가 실제로 사용하면서 불편한 점을 하나씩 해결하다 보니 기능이 늘어났습니다.

```text
갤러리 차단
      ↓
글과 댓글 숨기기
      ↓
사용자와 특정 단어 차단
      ↓
이미지와 디시콘 차단
      ↓
사용자 메모와 글 미리 보기
      ↓
저장 방식 개선
      ↓
브라우저에서 바로 차단
      ↓
화면과 사용 편의 기능 추가
      ↓
코드 구조 정리
```

기능이 늘면서 단순히 “차단이 되는가”뿐 아니라 프로그램이 느려지지 않는지, 설정이 많아져도 잘 저장되는지, 기존 기능을 망가뜨리지 않고 새 기능을 추가할 수 있는지도 중요해졌습니다.

---

## 프로그램은 어떻게 작동하나요?

디시갤 차단기는 크게 네 부분으로 나뉩니다.

* **팝업과 설정 화면** — 사용자가 차단할 내용과 사용 방법을 정합니다.
* **페이지에서 작동하는 기능** — 디시인사이드 화면을 살펴보고 필요 없는 글이나 요소를 숨깁니다.
* **백그라운드 기능** — 강력 차단, 오른쪽 클릭 메뉴처럼 브라우저에서 처리해야 하는 일을 맡습니다.
* **저장 기능** — 차단 목록과 각종 설정을 브라우저에 저장합니다.

일반적인 기능은 사용자의 브라우저 안에서 처리됩니다.

별도의 서버에 가입하거나 프로그램을 따로 설치할 필요는 없습니다.

## 만들면서 해결한 문제

### 페이지를 연 뒤 새로 나타나는 내용

디시인사이드는 처음 화면을 열고 난 뒤에도 댓글이나 글, 이미지 같은 내용이 계속 새로 나타날 수 있습니다.

처음 한 번만 검사하면 이런 내용을 놓치게 됩니다.

반대로 화면 전체를 계속 다시 검사하면 브라우저가 불필요하게 많은 일을 하게 됩니다.

그래서 새로 생기거나 바뀐 부분을 찾아 필요한 곳만 다시 확인하도록 만들었습니다.

기술적으로는 `MutationObserver`, `requestAnimationFrame` 등을 이용합니다.

---

### 같은 내용이 여러 곳에서 다시 나타나는 문제

갤러리 주소 하나만 막아도 문제가 끝나지는 않습니다.

차단한 갤러리는 다음과 같은 곳에서 다시 나타날 수 있습니다.

* 검색 결과
* 최근 방문한 갤러리
* 화면 옆의 링크
* 다른 게시물에 들어 있는 링크
* 실시간 베스트
* 나중에 새로 만들어진 화면 요소

그래서 디시갤 차단기는 상황에 따라 주소 접근 자체를 막거나, 링크를 숨기거나, 화면에 나타난 내용을 가리는 방식을 함께 사용합니다.

---

### 차단 목록이 계속 늘어나는 문제

설정 몇 개를 저장하는 것과 수백 개의 사용자 정보를 저장하는 것은 다릅니다.

작은 설정은 크롬의 동기화 저장 공간을 사용하고, 사용자 차단 목록이나 이미지 기록처럼 커질 수 있는 자료는 브라우저의 로컬 저장 공간에 보관합니다.

사용자 차단 목록도 하나의 큰 목록에 전부 넣기보다 여러 묶음으로 나누어 저장하도록 개선했습니다.

이미지 차단은 주소만 기억하지 않고 이미지의 특징값도 함께 이용합니다. 따라서 같은 이미지의 주소가 달라져도 다시 알아볼 수 있습니다.

---

## 코드 구조도 정리하고 있습니다

처음에는 기능 수가 적어 대부분의 파일을 한곳에 두어도 큰 문제가 없었습니다.

하지만 기능이 계속 늘어나면서 한 파일이 너무 많은 일을 맡거나 서로 관계없는 기능이 가까이 섞이기 시작했습니다.

현재는 기능의 역할에 따라 다음과 같이 나누는 작업을 진행하고 있습니다.

```text
src/
├── background/   브라우저 뒤에서 처리하는 기능
├── content/      디시인사이드 화면에서 작동하는 기능
├── shared/       여러 기능에서 함께 쓰는 코드
└── ui/           팝업과 설정 화면
```

단순히 폴더를 보기 좋게 만드는 것이 목적은 아닙니다.

새 기능 하나를 고쳤을 때 관계없는 다른 기능까지 함께 고쳐야 하는 일을 줄이는 것이 목표입니다.

## 개인정보 보호

디시갤 차단기를 사용하기 위해 별도의 계정을 만들 필요가 없습니다.

개발자가 운영하는 별도의 사용자 정보 서버도 두고 있지 않습니다.

다음과 같은 추적 기능도 넣지 않았습니다.

* 이용자를 추적하는 분석 프로그램
* 추적용 픽셀
* 별도의 사용자 계정
* 개발자가 운영하는 사용자 정보 데이터베이스

대부분의 설정과 개인 자료는 사용자의 브라우저 안에 저장됩니다.

작은 설정 가운데 일부는 크롬의 동기화 기능을 사용할 수 있고, 사용자 차단 목록이나 메모, 이미지 기록처럼 큰 자료는 해당 브라우저에 저장됩니다.

일부 기능은 필요한 경우 디시인사이드에서 정보를 직접 가져옵니다.

## 사용 기술

개발 내용을 확인하려는 분을 위해 사용한 주요 기술을 정리했습니다.

| 구분         | 사용 기술                     |
| ---------- | ------------------------- |
| 프로그래밍 언어   | JavaScript                |
| 화면 구성      | HTML, CSS                 |
| 확장 프로그램    | Chrome Manifest V3        |
| 설정 및 자료 저장 | Chrome Storage API        |
| 네트워크 단계 차단 | Declarative Net Request   |
| 백그라운드 작업   | Service Worker            |
| 화면 변화 감지   | MutationObserver          |
| 브라우저 기능 연동 | Context Menus, Active Tab |
| 배포         | Chrome Web Store          |

별도의 프레임워크나 자체 서버는 사용하지 않습니다.

## 직접 실행하기

저장소를 내려받거나 복제한 뒤 다음 주소를 엽니다.

```text
chrome://extensions
```

그다음:

1. **개발자 모드**를 켭니다.
2. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
3. `manifest.json`이 있는 프로젝트 폴더를 선택합니다.

따로 설치해야 하는 개발 도구나 빌드 과정은 없습니다.

## 이 프로젝트에서 배운 점

처음에는 제가 쓸 기능이 제대로 작동하는지가 가장 중요했습니다.

하지만 실제 사용자가 생기고 기능이 늘면서 기준도 달라졌습니다.

새 기능을 만드는 것뿐 아니라 다음 문제를 함께 생각하게 됐습니다.

* 기능끼리 서로 영향을 주지 않게 만드는 방법
* 페이지가 계속 바뀌어도 가볍게 작동하게 만드는 방법
* 차단 자료가 늘어나도 안정적으로 저장하는 방법
* 기존 사용자의 설정을 깨뜨리지 않고 기능을 바꾸는 방법
* 코드가 커져도 다시 이해하고 고치기 쉬운 구조를 만드는 방법

개인적으로 필요한 작은 도구에서 시작했지만, 프로젝트를 유지하면서 **작동하는 코드를 만드는 것과 오래 관리할 수 있는 프로그램을 만드는 것은 다른 문제**라는 점을 배웠습니다.
