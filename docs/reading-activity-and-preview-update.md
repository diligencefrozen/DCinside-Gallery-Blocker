# 활동량 확인, 미리보기와 읽기 UI 변경

2026-11-16 · 7.3.52.2026 개발 작업. 기존 기록·필터 설정은 유지한다. manifest는 7.3.51.2026이며 버전 변경, 릴리스 빌드, 업로드는 수행하지 않았다.

## 활동량 판정과 이동 순서

기존에는 초기 설정·캐시 준비 뒤 idle/배치 검사를 거쳤으며, 성공 캐시 쓰기도 250ms 지연될 수 있었다. 빠른 클릭이나 페이지 이동이 먼저 일어나면 상세 페이지에서 다시 판정하는 모습이 생겼다.

PC 일반·마이너·미니·인물의 목록/상세에서 필요한 활동량 모듈을 document_start에 전달한다. 활성 목록의 초기·추가 행 검사는 idle/80ms 대기를 생략한다. 기존 동적 프로필과 중복 실행되지 않도록 모듈 가드를 유지한다.

목록의 회원 작성자가 확인되는 글 링크에만 이동 검사를 적용한다. 신뢰할 수 있는 실제 클릭/가운데 클릭을 대상으로 하며 목적지와 gallery ID·글 번호를 검증한다. 저활동이면 목록 행을 숨기고 상세 요청을 보내지 않는다. 미확인 클릭에는 ‘활동 확인 중…’과 취소를 표시한다. 조회 실패·요청 제한은 저활동으로 해석하지 않으며 ‘확인 없이 열기’ 또는 취소를 제공한다. 필터 OFF와 익명·무관한 링크는 기존 이동을 유지한다.

기존 UID별 중복 조회 방지, 3초 간격·10분당 12회 요청 제한과 캐시를 재사용한다. 첫 조회의 네트워크 대기는 남는다. 한도를 늘리거나 실패한 회원을 자동 차단하지 않는다. 가운데/Ctrl/Shift 클릭은 판정 후 검증된 background 메시지로 요청한 탭/창을 열어 비동기 팝업 차단을 피한다. 다른 작성자로 재사용된 행, 바뀐 링크, 취소된 요청과 이전 페이지의 응답은 이동시키지 않는다. 확인 완료와 설정 OFF가 동시에 발생하거나 확인 없이 열기를 연속 클릭하더라도 같은 이동 요청의 새 탭/창은 한 번만 연다.

저활동 성공 결과는 캐시를 즉시 쓰며, 확인 후 이동할 때는 대기 중인 캐시 쓰기를 기다린다. 쓰기는 직렬화하고 기존 탭 간 lock/병합을 유지한다. 캐시 삭제는 기존 쓰기를 기다리므로 늦은 쓰기가 삭제 내용을 복구하지 않는다. 저장 실패는 메모리 판정까지 없애지 않으며 로그인·조회 실패를 성공으로 가장하지 않는다.

## 실제 동영상 확인

사용자가 제보한 [마이너 갤러리 글](https://gall.dcinside.com/mgallery/board/view/?id=moshua911&no=53168&page=1)을 두 엔진에서 읽어 실제 미리보기 파서·movie iframe 전처리·표시 경로로 재생했다. 글 HTTP 200 → 플레이어 HTTP 200 → 미디어 HTTP 206 `video/mp4`, 클릭 뒤 재생 시간 증가와 일시정지를 확인했다. MediaError는 양쪽 모두 0이다.

해당 영상은 720×1562 세로 영상이다. 기존 렌더에서는 높이 1562px로 보여 네이티브 조작부가 미리보기 아래로 밀렸다. 변경 후 영상 높이 374px, 재생 UI 포함 419px로 미리보기 스크롤 영역 498/500px 안에 들어온다. 원문 링크는 원래 글 주소를 사용한다. CDN/인증·리퍼러 우회, 미디어 다운로드나 자동 재생 강제는 추가하지 않았다. 진단에는 도메인·상태만 기록하고 서명된 미디어 쿼리는 기록하지 않는다. 범위 요청 중단/캐시 관련 브라우저 요청 이벤트가 있어도 실제 재생 성공과 MediaError를 별도로 확인한다. 닫기·다시 렌더링 시 일반 동영상을 일시정지한다.

## 범위와 제약

댓글 수는 `comment_total_<현재 글 번호>`와 해당 댓글 머리말의 native 전체 수를 사용한다. 다른 글, 미리보기, 실제 렌더된 댓글 행 수를 전체 수로 오인하지 않는다. 수를 확인할 수 없으면 숫자를 숨기고 이동 기능은 유지한다. 댓글 버튼과 ↑ 버튼은 같은 그룹으로 쌓으며 기존 자동 새로고침·플로팅 UI와의 충돌 회피를 유지한다.

AI 변경은 표시만 바꾼다. 모델·판정 기준·네트워크 전송·기본 OFF는 변경하지 않으며, AI 판단 오류 가능성과 원문 확인 경로를 제공한다. 모션은 220ms이고 동작 줄이기에서는 제거한다.

자동 기록 가져오기는 현재 브라우저 프로필의 HTTPS PC 사이트 저장소 대상이다. 다른 기기·프로필·서버 계정 전체 목록 수집을 보장하지 않는다. 실제 데이터가 있는 사용자 로그인 프로필의 최종 검증은 남아 있다. 갤러리별 차단·OFF 규칙·불확실한 식별자는 보류하며 필터를 자동으로 켜지 않는다. 공식 메모 백업·붙여넣기는 유지한다. 자세한 모델과 데이터 보존은 [자동 수집 보고서](automatic-records-and-scroll-top.md)를 참고한다.

디시 자체 외부 링크 경고 강제 OFF는 기존 구현을 유지한다. 사용자가 외부 사이트로 이동할 때 디시가 제공하던 안내가 제거된다. 브라우저 세이프 브라우징·인증서 경고나 디시 이외 사이트의 경고는 변경하지 않는다. 추가 확장 권한은 없다.

## 검증

격리된 Playwright Chromium·Firefox를 사용했다. 사용자 브라우저 프로필과 로그인 기록은 읽거나 수정하지 않았다. 합성 목록·댓글 검사와 실제 공개 동영상 검사를 구분한다.

- Node 단위·계약 검사: 55/55 통과.
- 활동량 이동 최종 검사: 24/24 통과. 설정 초기화·늦은 캐시·동시 클릭·취소·UID/링크 재사용·일반/가운데/수정키 클릭·OFF/실패·중복 새 탭 방지 포함.
- 실제 설치형 Chromium 통합 검사: 모델 점수·AI 가림·팝업/옵션·OFF 해제·작성자 도구 경계 검사 통과. 백그라운드 탭의 비동기 fitting 완료 전에 측정하던 테스트는 활성화·준비 대기로 수정했다.
- 전체 브라우저 묶음: 166건 중 162건 통과, 실패 0, 선택적 연속 스크롤/상호작용 성능 프로필 4건 건너뜀. 약 331초. 실제 설치형 양 엔진의 가져오기·되돌리기, 자동 수집, 기존 파일·붙여넣기, 메모·댓글·미리보기·outlink 경고 동작을 포함한다. 묶음에서 활동량 22건을 통과한 뒤 발견한 중복 새 탭 경합은 최종 24건으로 별도 재검증했다.
- 사진·영상 새 회귀 검사: 양 엔진 4/4 통과. 로컬 생성 WebM으로 실제 디코딩·클릭·일시정지·닫기 정지·오류/재시도·GIF/DCCon 제외·반복 렌더·좁은 화면을 검사한다. 실제 제보 글의 MP4 검사는 별도 진단 JSON으로 구분한다.
- 기존 미리보기 회귀 스크립트 통과. 전체 묶음의 댓글 작성 88개 및 추천 43개 합성 시나리오도 통과했으며 실제 사이트에 쓰는 요청은 보내지 않았다.

검증 로그·안전한 영상 진단 JSON·UI 스크린샷은 `test-results/reading-ui-final`의 검토용 전체 소스 ZIP에 함께 첨부한다. ZIP은 스토어 업로드용 릴리스 빌드가 아니며 소스 파일을 그대로 묶은 스냅샷이다.

재현 명령은 `node --test --test-isolation=none tests/*.test.mjs`, `node --test --test-concurrency=1 --test-force-exit tests/*.test.cjs`, `node tests/extension-integration.cjs`, `node tests/preview-regression.cjs`다. 이 Windows 검사 환경에서는 Firefox DLL 사전 검사 오판을 피하기 위해 `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1`을 설정했다. 양쪽 실제 브라우저 프로세스 실행과 재생·상호작용은 별도로 성공했다.

소스 실행은 ZIP을 풀고 루트 `manifest.json`이 있는 폴더를 Chrome 확장 관리의 압축해제 확장으로 로드하거나 Firefox `about:debugging`에서 임시 부가 기능으로 로드한다. 기존 개발 확장을 사용 중이라면 확장을 다시 로드하고 열려 있던 옵션·디시 페이지도 새로고침한다. 이전 ‘목록 창 열기 필요’ 안내는 현재 옵션 소스에 없다. 테스트 의존성이 없는 환경은 먼저 `pnpm install --frozen-lockfile`과 Playwright 브라우저 준비가 필요하다. 후속 미리보기 이동·순번·시크릿 지원은 [최신 보고서](preview-navigation-and-private-import.md)에 기록했다.

변경 코드는 활동량 서비스·목록 필터·새 background 이동 메시지, manifest 초기 전달, 미리보기 렌더러, 표현 감지 안내, 상단/댓글 이동, 옵션 가져오기 UI와 해당 회귀 검사에 있다. 기존 차단·메모 저장 모델과 outlink 구현에는 이번 단계에서 추가 변경하지 않았다.
