# 미리보기 댓글 정렬 및 활동량 검증 — 2026-11-14

버전은 7.3.51.2026을 유지한다. 기준 비교는 `c240b9e` → `e332590`의 댓글/활동량 수정과 이번 세션 토큰 재개 보완이다. 기존 사용자 설정·차단·메모·캐시 스키마와 서버 요청 예산은 변경하지 않았다.

## 확인된 원인과 수정

- 활동량 배지의 호스트 선택자가 문서 순서상 댓글 메타 그리드를 먼저 선택했다. 배지가 세 번째 그리드 항목으로 추가되어 닉네임이 오른쪽으로 이동했다. 생성 시부터 작성자와 액션 영역을 분리하고 배지는 액션 영역 내부에만 배치한다.
- 답글 버튼 정비가 기존 버튼을 매번 지우고 다시 만들었다. 일반 span을 날짜로 이동하면서 활동량 배지까지 날짜로 취급할 수 있었다. 날짜만 선별하고 기존 답글/삭제 버튼과 포커스를 유지한다. 날짜 문자열도 바뀔 때만 갱신한다.
- 댓글 행과 내부 작성자를 각각 작성자로 수집했다. 실제 작성자로 정규화하여 중복 수집을 방지한다. 추가 댓글은 추가된 행만 스캔하고 여러 스캔 요청은 한 배치로 처리한다.
- 최초 조회에 세션 토큰이 없으면 실패 캐시가 토큰이 생긴 후에도 유효했다. 토큰이 생기면 NO_TOKEN 캐시를 무효화하고, 재진입·화면 재평가 외에도 작성자 hover/focus 시 필요한 조회를 재개한다. 예산/서버 제한 실패는 이 경로로 무시하지 않는다.
- 화면 밖의 표시 전용 활동량은 IntersectionObserver로 대기한다. 닫힌 미리보기는 조회 대상과 재시도 타이머를 해제하고, 늦은 응답이 새 대기열을 삭제하지 않도록 한다. 성공 결과는 재열기에서 캐시로 표시한다.

## 측정 범위와 결과

Windows, Playwright Chromium 151.0.7922.34 및 Firefox 153.0의 실제 headless 엔진. 공식 서버를 호출하지 않는 비식별 합성 데이터와 모킹한 확장 API를 사용했다. 기준 소스와 수정 소스는 동일 fixture로 순차 실행했다.

아래는 **분리된 댓글 DOM에서 답글 액션 정비 함수를 5회 호출한 중앙값**이다. 전체 페이지 성능이나 입력 지연으로 일반화할 수 없다. Firefox의 낮은 시간 해상도 때문에 50개 결과 0ms는 측정 해상도 미만을 뜻한다.

실제 미리보기 렌더 경로에서도 2,000개 중 처음 80개만 마운트하고, 추가 펼침에서 80개만 더 처리했다. 작성기 iframe은 본문·댓글 읽기 중 생성되지 않았다. 동일 작성자 미리보기 20회 재열기에서 모킹한 활동량 요청은 총 1회였다. 닫은 뒤 미리보기 iframe과 해당 활동량 대기열·타이머는 0이었다. 이는 확장 전체의 모든 타이머/Observer가 0이라는 의미는 아니다.
