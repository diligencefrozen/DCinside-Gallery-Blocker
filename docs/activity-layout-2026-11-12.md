# 디시갤 차단기 활동량·이미지 보기 개선

기준은 첨부된 DCinside-Gallery-Blocker-develop.zip의 v7.3.51.2026 소스다. 패키지에는 사용자 백업, 합성 시험 데이터 또는 프로필이 포함되지 않는다.

## 원인과 수정

- 활동량이 작성자 가상 요소에 붙어 원래 작성자 폭 계산과 충돌했다. 목록에서는 제목 셀 오른쪽, 댓글·답글에서는 시간과 삭제 버튼이 있는 메타 영역에 전용 배지를 둔다. 제목 셀의 테이블 표시 방식과 원래 링크를 유지한다. 좁은 화면에서는 배지를 숨긴다.
- Firefox 기능 주입과 두 브라우저의 조회 서비스가 활동 차단 스위치에 종속돼 있었다. 활동량 표시만 켜도 가시 범위의 회원을 기존 캐시·요청 큐로 조회한다. 차단 판정은 차단 설정이 켜진 대상에만 적용한다. 비회원은 조회하지 않으며 토큰 부재·제한·응답 오류·불완전한 숫자는 0으로 표시하지 않는다.
- 같은 UID의 댓글이 많으면 행 하나를 등록할 때마다 앞선 행 전체에 대기 상태를 다시 적용했다. 등록 중에는 새 행만 처리하고 조회 완료 시 결과를 공유한다. 키워드 안내 DOM은 요소별로 재사용하며 이미지를 검사할 때 중첩된 변경 영역과 작성자 판별을 묶었다.
- 작성자 이미지 숨김을 해제해도 저장 URL의 CSS 가림이 남고, 키워드로 접힌 본문을 다시 그리면 프레임에 있던 임시 보기 상태가 사라졌다. 한 번의 보기 동작이 두 가림을 함께 해제하고, 같은 미리보기에서 본문이 교체되어도 해당 URL의 상태를 복원한다. 닫거나 게시글을 바꾸면 초기화한다. 영구 차단 목록의 삭제는 차단 해제 동작으로만 수행한다.
- 팝업 화면·편의와 옵션은 같은 토글과 범위 선택기를 사용한다. 디시 기록 가져오기는 기존 공식 메모 가져오기 화면을 열고 확장 백업 복원으로 가는 경로도 제공한다. PC·모바일 공식 메모는 기존 파서와 충돌 미리보기·백업·실행 취소를 재사용한다. 공식 앱과 웹 차단 목록의 미확인 형식에는 가져오기 기능을 추가하지 않았다.

## 측정 결과

Windows, 실제 Chromium·Firefox의 격리 페이지에서 프로덕션 모듈을 실행했다. 100행 목록과 50/500/2000댓글을 함께 표시하고 동일 회원을 반복 배치했다. 응답은 스크립트 로드 시작부터 첫 rAF까지로, 실제 클릭 지연과는 다르다. 프레임 간격 p95는 45개 rAF 표본 기준이다. 각 조합은 한 번씩 측정했다. 요청 수는 합성 응답을 반환하는 활동량 브리지 호출 수다. 실제 서버 왕복 시간과 다수의 서로 다른 UID가 한도를 소진하는 상황은 이 수치에 포함되지 않는다.

## 파일과 검증

- 활동량과 레이아웃: src/content/image/image-account-filter.js, src/content/user/account-activity-blocker.js, src/content/core/feature-loader.js, src/content/appearance/writer-layout.css
- 미리보기와 숨김: src/content/image/image-blocker.js, src/content/keyword/keyword-hider.js, src/content/core/content_script.js
- 설정과 가져오기: src/ui/shared/writer-preferences.js, src/ui/popup/popup.html, src/ui/popup/popup.js, src/ui/options/options.html, src/ui/options/options.js
- 회귀·계측: tests/activity-layout.test.cjs, tests/activity-layout-profile.cjs, tests/image-first-paint.test.cjs, tests/writer-preferences.test.cjs
- 실제 확장을 로드해 두 브라우저에서 11월 백업의 비식별 설정으로 본문 미리보기를 각 21회 열었다. 브라우저 모듈 회귀에서는 활동량 표시 단독 조회, 배지 위치, 키워드 접기와 이미지 숨김이 함께 적용된 본문의 복원, 영구 기록 보존 및 다시 그리기를 검증했다. 팝업·옵션의 양방향 동기화와 가져오기 진입은 Chromium 확장에서 검증했다.
- 수정 후 스크린샷과 원시 측정표는 test-results/layout-1112/에 있다. 사진은 실제 브라우저에서 합성 게시글을 렌더링해 촬영했다. 로그인 실계정 활동량 서버 호출, 실제 서비스 배포 및 공앱 백업 호환성은 검증하지 않았다.
