# 미리보기 이동·첫 진입·시크릿 기록 가져오기

2026-11-17 · 7.3.52.2026 개발 작업. 이전 검증 기준은 `72d4360`이며 진행 중인 변경은 사용자가 `3df4efa`에 커밋했다. 이후 중첩 YouTube 보존과 추가 검증을 보강했다. 현재 기준 소스의 manifest 버전 7.3.52.2026, 확장 권한, 차단·메모 저장 모델은 유지한다. 이번 단계에서 추가 버전 변경·릴리스 빌드·업로드는 수행하지 않았다.

## 사진과 미리보기 이동

첨부 화면에서 사진 하나에 중앙의 1과 좌측의 2가 함께 나타나는 문제를 기준으로, 중첩 native wrapper·sprite·이전 확장 배지와 디시 CSS를 결합한 fixture를 만들었다. 디시의 `.num.img`/`.imgnum` 클래스를 새 배지에 재사용하던 결합을 제거하고 중첩 wrapper와 중복 배지를 복구한다. 이제 본문 사진마다 좌측 상단 8px에 배지 한 개를 둔다. 동적 추가/삭제·재직렬화·다시 열기에서도 순번을 재계산한다. 작은 아이콘·디시콘·댓글 이미지·영상 썸네일은 제외한다. 제보 사진 글의 URL은 제공되지 않아 해당 글의 실사이트 HTML 자체를 확인한 결과는 아니다.

미리보기 오른쪽 아래에 ↑·댓글 이동 그룹을 둔다. 원래 페이지가 아니라 `.dcbpv-scroll`만 이동하며, 댓글 이동은 내부 댓글 제목으로 키보드 초점도 옮긴다. 위로 버튼은 스크롤 후 표시한다. header/footer·스크롤바·고정 댓글 입력창과 공간을 구분하고, 디시콘 선택기가 열린 동안 숨긴다. 창·입력창의 크기가 바뀌면 재배치한다. 닫으면 프레임 예약·이벤트·observer를 해제한다. 동작 줄이기를 지원한다.

댓글 전체 수는 새 `commentTotal` 필드로 표시한다. 현재 글의 native `comment_total_<no>` 또는 해당 댓글 영역의 ‘전체 댓글 N개’만 사용한다. 렌더된 일부 댓글 수, 본문/제목의 숫자와 다른 글의 수는 전체 수로 승격하지 않는다. 0·쉼표·확인 불가를 구별하며 확인 불가이면 숫자를 숨긴다. 등록/삭제 결과가 전체 수를 명확히 제공하면 갱신한다.

## 첫 진입 최적화와 측정

기존 파서는 본문을 찾기 전에 전체 문서의 모든 이미지·동영상·iframe을 정규화했다. 이후 본문·댓글 복사본을 다시 정규화하므로 sidebar와 아직 읽지 않을 댓글까지 중복 처리했다. 작성자도 header에서 이미 찾았는데 전체 댓글과 sidebar의 회원 선택자를 모두 조회했다.

전체 문서 변형을 제거하고, 실제 본문·댓글 복사본의 정규화와 sanitizer를 유지한다. 작성자는 기존 우선순위를 유지하며 첫 유효한 header 일치에서 탐색을 끝낸다. 댓글의 viewport 지연 처리, 이미지 lazy loading, 필터 확인 전 가림, 캐시와 요청 제한은 유지한다. 인접 wrapper 안의 YouTube metadata가 기존 문서 변형에 의존하던 회귀는, 원래 본문의 형제 범위에서 검증된 marker만 복사하도록 보강했다. 댓글·sidebar·위장 호스트와 중복은 제외한다.

Windows / 격리 Playwright Chromium·Firefox / 같은 합성 HTML(본문 사진 2개, 댓글 500개, sidebar 이미지 1,000개) / 서로 다른 글 번호 5회 / 네트워크 응답 fixture. 화면에 붙고 필터 확인을 마친 첫 본문을 rAF로 관찰했다. GPU paint 완료나 실서비스 서버 응답시간 측정은 아니다.

| 지표 | Chromium 전 → 후 | Firefox 전 → 후 |
|---|---|---|
| 첫 본문 프레임 중앙값 | 133.4 → 25.0ms | 303 → 31ms |
| 새 브라우저의 첫 표본 | 333.3 → 239.2ms | 463 → 91ms |
| 파싱 중앙값 | 121.6 → 10.3ms | 293 → 18ms |
| 전체 문서 미디어 정규화 방문 | 1,502 → 0 | 1,502 → 0 |

초기 폰트·스타일·엔진 준비 비용은 남는다. Chrome 계열의 첫 표본은 여전히 약 239ms였으며 항상 즉시 열리거나 모든 프레임이 16ms 이내라고 주장하지 않는다. Firefox의 Long Task API 표본 0은 지원/관측 차이를 포함하므로 긴 작업이 없다는 뜻으로 해석하지 않는다. 비교 JSON은 `test-results/preview-startup/{before,after}/*-profile.json`에 있다.

## 활동 확인 안내

실시간베스트 제목 옆에서 ‘활동 확인 불가·확인 없이 열기·취소’가 원출처 확인 배지와 겹치던 안내를 제목 셀 아래 독립된 진한 카드로 바꿨다. normal flow에서 행 높이를 늘리므로 작성자 열과 다음 행을 덮지 않는다. 확인 중/실패 문구, 확인 없이 열기와 취소, 취소 후 제목으로 초점 복원을 제공한다. 180ms 등장 효과와 동작 줄이기·좁은 열·다크 모드·키보드 Tab/Enter를 검사했다. 활동량 판정·요청 예산·원출처 확인·새 탭 guard는 바꾸지 않았다.

## 자동 수집과 일반·시크릿 출처

사용자가 제공한 `#issue_setting`, `open_user_block`, `UserMemo.openConf()`는 사이트의 기록 UI 진입점이다. 자동 가져오기는 앞서 공개 사이트 구현에서 확인한 동일 저장 항목 `block_all`, `block_parts`, `user_memo`를 읽어 전체/등록된 갤러리별 범위를 순회한다. 각 갤러리의 메뉴를 열거나 토글·저장을 실행하지 않는다. 사용자가 디시 갤러리나 모달을 직접 열 필요가 없다.

대상은 ‘현재 옵션 창과 같은 모드’가 기본이며 일반/시크릿을 명시적으로 선택할 수 있다. 브라우저의 window metadata로 맞는 창을 고르고 `windowId`를 지정해 임시 비활성 탭을 연다. 생성·준비·읽기 후 탭의 창/시크릿 정보를 확인하고 content script의 모드 정보도 비교한다. 선택한 모드가 실패하면 다른 모드로 fallback하지 않는다. 종료된 시크릿 세션의 사라진 사이트 기록은 복원하지 않는다. 접근 허용은 브라우저 설정을 따른다. 확장이 이를 켜거나 인증 정보를 수집하지 않는다.

사이트의 일반/시크릿 기록은 분리되지만, 가져오기를 적용하면 기존 확장 저장소에 보관되어 일반 창에서도 보인다. 이 지속성을 대상 설명에 표시한다. Chrome의 확장 저장소 공유 동작은 [공식 incognito 문서](https://developer.chrome.com/docs/extensions/reference/manifest/incognito)에 설명되어 있다. 접근 확인은 [Firefox 공식 API 문서](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/extension/isAllowedIncognitoAccess)의 브라우저 제공 값을 사용한다.

갤러리별 메모의 기존 범위 보존, OFF/갤러리별 차단·불확실한 식별자 보류, 병합/미리보기/명시적 적용/undo, 백업·붙여넣기 대체 경로와 필터 활성 상태는 유지한다. 실제 사용자 로그인 프로필의 등록 기록을 읽은 검증은 여전히 남아 있다. 이번 실제 설치형 검사는 새 프로필에 넣은 합성 기록만 사용했다.

## 검증과 실행

- 전체 브라우저 묶음: 178건 중 174 통과, 실패 0, 선택 성능 4건 제외. 약 353초. 새 사진 배치·내부 이동·활동 확인 카드와 기존 차단·메모·미리보기·가져오기·undo 포함.
- 최종 단위·계약 검사 60/60 통과(창 모드 선택·권한·세션 없음·오류 정리·잘못된 탭 모드 검증 5건 포함). 전체 브라우저 묶음 시작 뒤 추가된 실제 installed private 2건과 중첩 YouTube 2건은 별도 4/4 통과 로그로 구분한다.
- Chromium·Firefox의 실제 설치형에서 일반·시크릿 출처에 서로 다른 합성 기록을 넣고, 올바른 미리보기/대상 표시/적용 전 확장 저장소 불변/사이트 원본 불변/임시 탭 정리를 확인했다.
- Chromium 테스트는 새 격리 프로필의 실제 ‘Allow in Incognito’ 스위치를 사용한다. 이 빌드의 command-line unpacked extension은 해당 변경 뒤 reloading 상태가 남아 테스트 프로필을 재시작·재활성화했다. 이는 테스트 준비이며 제품 코드가 브라우저 허용을 변경하는 기능은 없다. Firefox는 공식 BiDi `moz:allowPrivateBrowsing` 옵션으로 새 테스트 부가 기능에만 접근을 허용했다.
- 이전 전체 묶음 후의 YouTube 보강은 새 adjacent YouTube·startup·native video 두 엔진 6/6 검사로 확인했다. 기존 미리보기 회귀 스크립트도 통과했다.

의존성 준비는 `pnpm install --frozen-lockfile`과 Playwright 브라우저 설치를 사용한다. 실행 검사는 `node --test --test-isolation=none tests/*.test.mjs`, `node --test --test-concurrency=1 --test-force-exit tests/*.test.cjs`다. 이 Windows 환경에서는 Firefox DLL 사전 검사의 오판 때문에 `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1`을 설정했으며 실제 브라우저 프로세스와 상호작용을 확인했다.

검토용 전체 소스 ZIP은 `test-results/preview-followup-final`에 생성하며 로그·측정 JSON·UI 스크린샷을 포함한다. 압축을 푼 루트 manifest 폴더로 개발 확장을 다시 로드하고 열려 있던 옵션·디시 페이지를 새로고침한다. 원래 차단·메모를 초기화할 필요는 없다. 변경 파일 목록은 ZIP의 검증 JSON에 있다.
